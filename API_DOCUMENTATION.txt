IAS Backend - API Documentation
===============================

Base URL:
http://localhost:3000/api/v1

Nota: los endpoints que requieren autenticación JWT deben usar el header:
Authorization: Bearer {{JWT_TOKEN}}

1) AUTHENTICATION
-----------------

POST /auth/register
- Descripción: Registrar un nuevo usuario en el sistema.
- Autenticación: No requerida.
- Body JSON:
  {
    "email": "usuario@cooperativa.com",
    "password": "SecurePassword123!",
    "name": "Juan",
    "lastname": "Pérez"
  }
- Ejemplo Postman:
  Método: POST
  URL: http://localhost:3000/api/v1/auth/register
  Body > raw > JSON
- Respuesta esperada: accessToken, user {id, email, name, lastname, role}

POST /auth/login
- Descripción: Iniciar sesión y obtener token JWT.
- Autenticación: No requerida.
- Body JSON:
  {
    "email": "usuario@cooperativa.com",
    "password": "SecurePassword123!"
  }
- Ejemplo Postman:
  Método: POST
  URL: http://localhost:3000/api/v1/auth/login
  Body > raw > JSON
- Respuesta esperada: accessToken, user {id, email, name, lastname, role}

GET /auth/profile
- Descripción: Obtener perfil del usuario autenticado.
- Autenticación: Requiere JWT.
- Headers:
  Authorization: Bearer {{JWT_TOKEN}}
- Ejemplo Postman:
  Método: GET
  URL: http://localhost:3000/api/v1/auth/profile
- Respuesta esperada: Datos del usuario actual.

2) USERS
--------

GET /users
- Descripción: Obtener todos los usuarios registrados.
- Autenticación: Requiere JWT.
- Ejemplo Postman:
  GET http://localhost:3000/api/v1/users
  Header: Authorization: Bearer {{JWT_TOKEN}}

GET /users/stats
- Descripción: Obtener estadísticas de usuarios por rol.
- Autenticación: Requiere JWT.
- Ejemplo Postman:
  GET http://localhost:3000/api/v1/users/stats

GET /users/:id
- Descripción: Obtener información de un usuario por su UUID.
- Autenticación: Requiere JWT.
- Ejemplo Postman:
  GET http://localhost:3000/api/v1/users/123e4567-e89b-12d3-a456-426614174000

PATCH /users/:id
- Descripción: Actualizar nombre y apellido de un usuario.
- Autenticación: Requiere JWT.
- Body JSON:
  {
    "name": "NuevoNombre",
    "lastname": "NuevoApellido"
  }
- Ejemplo Postman:
  PATCH http://localhost:3000/api/v1/users/123e4567-e89b-12d3-a456-426614174000

DELETE /users/:id
- Descripción: Eliminar un usuario del sistema.
- Autenticación: Requiere JWT.
- Ejemplo Postman:
  DELETE http://localhost:3000/api/v1/users/123e4567-e89b-12d3-a456-426614174000

4) EVENTS
---------

POST /events
- Descripción: Crear un evento generado por el sistema IA.
- Autenticación: Requiere JWT.
- Body JSON:
  {
    "cameraId": "123e4567-e89b-12d3-a456-426614174000",
    "type": "persona_detectada",
    "description": "Persona entrando a la sucursal",
    "location": "Entrada frontal",
    "imageUrl": "https://cdn.example.com/event1.jpg",
    "confidence": 0.92,
    "priority": "MEDIA",
    "status": "PENDIENTE"
  }
- Ejemplo Postman:
  POST http://localhost:3000/api/v1/events

GET /events
- Descripción: Obtener lista de eventos, con filtros opcionales.
- Autenticación: No requerida.
- Query params opcionales:
  cameraId, status, priority
- Ejemplos Postman:
  GET http://localhost:3000/api/v1/events
  GET http://localhost:3000/api/v1/events?status=PENDIENTE
  GET http://localhost:3000/api/v1/events?cameraId=123e4567-e89b-12d3-a456-426614174000&priority=ALTA

GET /events/pending
- Descripción: Obtener solo los eventos pendientes de revisión.
- Autenticación: No requerida.
- Ejemplo Postman:
  GET http://localhost:3000/api/v1/events/pending

GET /events/stats
- Descripción: Obtener estadísticas de eventos.
- Autenticación: No requerida.
- Ejemplo Postman:

GET /events/camera/:cameraId
- Descripción: Obtener eventos de una cámara específica.
- Autenticación: No requerida.
- Ejemplo Postman:
  GET http://localhost:3000/api/v1/events/camera/123e4567-e89b-12d3-a456-426614174000

GET /events/:id
- Descripción: Obtener un evento por su UUID.
- Autenticación: No requerida.
- Ejemplo Postman:
  GET http://localhost:3000/api/v1/events/123e4567-e89b-12d3-a456-426614174000

PATCH /events/:id
- Descripción: Actualizar un evento (estado, reviewer, prioridad, etc.).
- Autenticación: Requiere JWT.
- Body JSON:

- Ejemplo Postman:

DELETE /events/:id
- Descripción: Eliminar un evento.
- Autenticación: Requiere JWT.

5) ALERTS
---------

- Descripción: Crear una alerta asociada a un evento.
- Autenticación: Requiere JWT.
- Body JSON:

    "eventId": "123e4567-e89b-12d3-a456-426614174000",
    "message": "Alerta de prueba: movimiento detectado",

  }
- Ejemplo Postman:
  POST http://localhost:3000/api/v1/alerts

GET /alerts
- Descripción: Obtener todas las alertas.
- Autenticación: Requiere JWT.
- Ejemplo Postman:

Uso rápido en Postman
---------------------
1. Crear colección "IAS Backend".
2. Registrar usuario: POST /auth/register.
3. Login: POST /auth/login.
4. Copiar el accessToken de la respuesta.
5. Agregar header global a las peticiones protegidas:
   Authorization: Bearer {{JWT_TOKEN}}
6. Usar los endpoints de /users, /cameras, /events y /alerts.

Notas finales
-------------
- El prefijo global de la API es /api/v1.
- Si la aplicación corre en un puerto distinto, ajustar la URL base.
- Para crear el superadmin directamente, usa el seed o inserta en la tabla users con role = 'superadmin'.
